## 2. End-to-End User Journeys & Flow Verification

### Flow A: Community Donor Journey
1. **Browse Campaigns**: User lands on `/` and views active campaigns with live financial metrics and trust score badge.
   - *Expected*: Shows raised vs. target BDT, number of verified milestones, and transparent trust score.
   - *Result*: **PASS** (Tested on `http://localhost:3000/`).
2. **Select Donation Amount**: User clicks on campaign (`/campaigns/flood-relief-kurigram`), selects preset (৳500, ৳1,000, ৳2,500) or types custom amount.
   - *Expected*: BDT amount dynamically reflects USD equivalent at fixed $1\text{ USD} = 120\text{ BDT}$ rate with zero platform fees displayed.
   - *Result*: **PASS**.
3. **Escrow Authorization**: User approves order via PayPal Sandbox.
   - *Expected*: Server validates order amount matching, creates `Donation` in escrow, credits double-entry ledger (`CREDIT_DONATION`), and increments campaign available balance.
   - *Result*: **PASS** (Guarded by server-side order and capture verification).
4. **Receipt Generation**: Donor sees friendly thank-you message with receipt code (`SKH-...`) and PayPal batch reference.
   - *Expected*: Clean receipt card, option to donate anonymously on public timeline, no funds deducted on cancellation.
   - *Result*: **PASS**.

### Flow B: Volunteer Field Evidence Journey
1. **Passcode-Free Signed Access**: Volunteer receives invite link `/volunteer/[signed-jwt-token]` generated by coordinator.
   - *Expected*: Validates 7-day signed token via `jose`; loads only milestones assigned to that volunteer.
   - *Result*: **PASS** (Tested with volunteer session tokens).
2. **Review Checklist**: Milestone displays human-readable checklist ("Cash memo from fuel depot", "Photo of loaded fuel jerrycans on rescue boat").
   - *Expected*: Friendly items with status indicators and allocated budget in BDT.
   - *Result*: **PASS**.
3. **Capture & Upload Proof**: Volunteer taps large 64px camera-friendly upload button, selects photos or takes pictures on mobile.
   - *Expected*: Enforces $\le 6$ photos, $\le 8$ MB each, JPEG/PNG/WebP magic bytes.
   - *Result*: **PASS**.
4. **Duplicate Rejection**: Volunteer uploads a photo previously submitted for another milestone.
   - *Expected*: Server detects SHA-256 or perceptual dHash collision ($\le 5$ bits Hamming distance), rejects with friendly error: *"Duplicate photo detected... Please provide original, unique photographs"*, and logs `DUPLICATE_PROOF_REJECTED` in `AuditLog`.
   - *Result*: **PASS** (Verified in `tests/security_edge_cases.test.ts`).
5. **Submission Confirmation**: Volunteer sees: *"Thank you. We are checking your proof now."* Status changes to `proof_submitted`.
   - *Expected*: Photos saved under `/uploads` with strict path traversal containment; database updated atomically.
   - *Result*: **PASS**.

### Flow C: AI Forensic Audit & Verification Journey
1. **Multimodal Audit**: Verifier inspects evidence photos against checklist items and milestone budget.
   - *Expected*: Never hallucinates numbers; evaluates untrusted image text without executing instructions (prompt injection defense).
   - *Result*: **PASS**.
2. **Bangla Numerals Parsing**: Receipt handwritten or printed with Bengali digits (`১২,০০০ টাকা`).
   - *Expected*: Verifier accurately recognizes Bengali script and parses numeric total as `12000` BDT.
   - *Result*: **PASS** (Tested in `tests/security_edge_cases.test.ts`).
3. **Blurry Image Handling**: Photo is blurry or out-of-focus (Laplacian edge variance $< 100$).
   - *Expected*: Flags blurriness in `redFlags`, lowers confidence ($< 0.75$), sets verdict to `needs_more_proof`, and requires human review.
   - *Result*: **PASS**.
4. **10% Budget Variance Rule**: Receipt total deviates by $> 10\%$ from allocated milestone budget.
   - *Expected*: Deterministic post-check prevents `approved` verdict; downgrades to `needs_more_proof` with explanation.
   - *Result*: **PASS** (Tested in `tests/verifier.test.ts`).
5. **Missing API Key Fallback**: `AI_PROVIDER=gemini` or `anthropic` requested without `API_KEY` set.
   - *Expected*: Does NOT crash. Returns polite setup instruction message; funds remain locked in escrow.
   - *Result*: **PASS** (Tested in `tests/verifier.test.ts`).

### Flow D: Milestone Disbursement & Payout Journey
1. **Automated Payout**: Unflagged verification approved with $\ge 75\%$ confidence.
   - *Expected*: Automatically dispatches PayPal Payout to volunteer email; derives idempotent `senderBatchId` and `senderItemId`.
   - *Result*: **PASS**.
2. **Double-Spend Prevention**: Re-running disbursement on already-paid milestone.
   - *Expected*: Transaction detects existing `Payout` or status `RELEASED` and rejects duplicate disbursement attempt.
   - *Result*: **PASS** (Tested in `tests/payouts.test.ts`).
3. **Cryptographic Certificate**: Milestone paid out triggers automatic certificate creation (`/certificates/[code]`).
   - *Expected*: Generates SHA-256 digital signature, displays official Sakkhi Witness Authority seal, printable layout.
   - *Result*: **PASS** (Tested on `http://localhost:3000/certificates/SKH-20261028-0042`).
4. **PayPal Outage Fault Tolerance**: PayPal API returns 503 or times out.
   - *Expected*: Payout is recorded as `status: "QUEUED_RETRY"`, milestone set to `PAYOUT_QUEUED`, funds stay safe; background worker retries via `retryQueuedPayouts()`.
   - *Result*: **PASS** (Tested in `tests/security_edge_cases.test.ts`).

### Flow E: Coordinator Admin & Governance Journey
1. **Passcode Protection**: Accessing `/admin` requires coordinator passcode (`sakkhi2026`).
   - *Expected*: Sets `httpOnly: true`, `sameSite: "lax"`, and `secure` session cookie.
   - *Result*: **PASS**.
2. **Review Flagged Queue**: Coordinator inspects milestones flagged for review.
   - *Expected*: Displays AI summary, evidence breakdown, red flags, and requires written reason for override.
   - *Result*: **PASS**.
3. **Permanent Milestone Rejection & Proportional Refunds**: Fraudulent or impossible milestone cancelled.
   - *Expected*: Calculates each donor's proportional share, creates `REFUND` ledger entries, executes PayPal capture refunds, sets milestone to `REJECTED_PERMANENTLY`.
   - *Result*: **PASS** (Tested in `tests/security_edge_cases.test.ts`).

## 6. Strict QA Bug Report & Risk Assessment

### Fixed Issues
1. **Missing AI API Key Crash**:
   - *Bug*: Selecting `gemini` or `anthropic` without setting environment keys threw an uncaught error.
   - *Fix*: Created `MissingApiKeyVerifier` returning friendly setup instructions (`verdict: "needs_more_proof"`, funds retained in escrow).
2. **Missing Accessible Labels on Volunteer Uploads**:
   - *Bug*: Photo thumbnail remove button lacked screen-reader description.
   - *Fix*: Added `aria-label="Remove photo [filename]"`.
3. **TrustScoreCard Prop Type Alignment**:
   - *Bug*: Test mock passed deprecated `metrics` object instead of root breakdown attributes.
   - *Fix*: Updated test fixture to match `TrustScoreBreakdown` schema (`ratingLabel`, `percentReleasedWithProof`).
4. **Dev Server Cache Invalidation**:
   - *Bug*: Running `npm run build` while `next dev` was active caused in-memory bundle mismatch (HTTP 404 on `/`).
   - *Fix*: Dev server cleanly restarted; all routes serving HTTP 200.
